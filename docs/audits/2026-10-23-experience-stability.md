# 现有体验收尾与稳定性

本轮基于 `codex/ui-image-workbench` 的 `db7083a`，保留已完成的图片优先工作台，集中处理启动状态和恢复入口。

## 改动与原因

- 模型目录加载失败时，晚返回的健康检查和授权切换不能重新启用生成按钮。健康检查先判断 HTTP 状态，不再把错误响应当作正常授权信息。
- 健康检查失败给出服务检查提示；恢复后只清除这次检查产生的提示，保留任务错误。
- 生成区在没有可用供应商时提供设置入口，在目录加载失败时提供手动刷新入口；刷新期间禁用该入口，保留提示词及现有表单。
- 首帧的生成按钮默认禁用；供应商解析继续控制后续可用状态。
- 使用现有按钮、语义色和页面结构，补充中文及英文文案。移除目录故障时重复、容易误导为 Codex 登录问题的提示；手机故障说明缩短为完整一句。
- 重新生成静态 JS、CSS、source map 并更新缓存标识。现有布局测试只同步了实际改变的缓存版本，没有放宽断言。

## 浏览器验收

隔离服务使用临时目录和本机模拟供应商，不读取用户真实配置或调用付费生成接口。

- 三轮目录故障恢复均通过：故障时禁用生成，点击刷新后恢复供应商并保留输入。分别使用“稳定性验证：保留提示词”“第二轮恢复验证”“第三轮恢复验证”检查读回。
- 无可用供应商时显示说明，点击入口确实打开系统设置的 API 设置页。
- 模拟 HTTP 400 后显示“修改输入与参数”，不提供无效重试；修正输入后任务完成。
- 新生成任务可在历史库打开详情并导出图片与提示词。导出 ZIP 完整性、PNG 解码和提示词内容均通过；这证明本地生成链路与导出契约，不代表真实模型生成质量。
- 已查看桌面 `1440×1000`、手机 `390×844`、深色 2 倍截图。局部改动沿用现有反馈，不新增动效；由主执行者自检，未做独立视觉评审。

本地证据位于工作区同级 `ui-review/stability/`：

- `empty/`：无供应商的桌面和手机截图。
- `reload/`：目录失败的桌面和手机截图。
- `dark/`：深色 2 倍截图。
- `frontend-tests.log`、`python-tests.log`：定向验证结果。
- `export-verification.json`、`verified-export.zip`：导出内容验证。
- `serve.py`：只用于本轮隔离环境的故障注入，不进入应用代码。

截图工具报告的 503 是主动注入的目录故障；无 src 图片为隐藏的 `addToGalleryPreview`，已通过 DOM 检查确认不可见。
